# Deep Audit Report: Oktopus

## Context

Oktopus — платформа диспетчеризации такси (Scala 3.3.7 + ZIO 2.1.9 backend, PostgreSQL 16, Flutter frontend). Мюнхен и пригород, 3-5 водителей на компанию. Проект в активной разработке, ещё не в продакшене.

Аудит проведён 2026-03-26. Проверены: архитектура, безопасность, БД, тесты, качество кода, соответствие требованиям.

---

## 1. CRITICAL — Исправить до продакшена

### 1.1 Rate Limiting: X-Forwarded-For Spoofing
- **Файл:** `api/src/main/scala/com/shevchyk/app/routes/UserRoutes.scala`
- **Проблема:** UserRoutes доверяет заголовку `X-Forwarded-For` для определения IP клиента при rate limiting. Этот заголовок легко подделать — атакующий может обойти rate limiter.
- **Сравнение:** AuthRoutes корректно использует `req.remoteAddress` (не подделывается).
- **Исправление:** Унифицировать — везде использовать `remoteAddress`. Если за reverse proxy — доверять X-Forwarded-For только от известных прокси.

### 1.2 WebSocket: JWT Token в URL
- **Файл:** `web/lib/modules/core/services/websocket_service.dart` (строка 27)
- **Проблема:** Auth token передаётся как query parameter: `ws://api/ws?token=$_token`. Токен попадает в логи сервера, логи прокси, историю браузера.
- **Примечание:** На бэкенде (WebSocketRoutes.scala) уже есть ticket-based механизм, но Flutter-клиент его не использует.
- **Исправление:** Использовать ticket-based auth — клиент получает одноразовый ticket через REST, передаёт его в WS URL вместо JWT.

### 1.3 [FIXED] Дублирование таблиц: `persons` vs `users`
> **Исправлено:** V6__Merge_users_into_persons.sql объединила таблицы (коммит 58dcbca).

- **Файл:** `api/src/main/resources/db/migration/V1__Create_schema.sql`
- **Проблема:** Две таблицы с пересекающимися полями (email, name, role, password_hash, company_id). Между ними нет FK. Это создаёт:
  - Рассинхронизацию данных (email в persons ≠ email в users)
  - Неясность — какая таблица "источник правды"
  - Невозможность JOIN между auth и бизнес-доменом
- **Исправление:** Объединить в одну таблицу или добавить FK `persons.id → users.id` и убрать дублирование полей.

### 1.4 [FIXED] Query Parameters без ограничений
> **Исправлено:** Добавлены .min().max() ограничения (коммит 9f569eb).

- **Файлы:** UserRoutes, AuditRoutes и другие
- **Проблема:** Параметры `limit`, `days`, `offset` не имеют верхней границы. Запрос с `limit=999999` выгрузит всю таблицу.
- **Исправление:** Добавить `.min(1).max(100)` (или другой разумный максимум) для всех query-параметров пагинации.

## 2. HIGH — Исправить до релиза

### 2.1 Default JWT Secret в dev-режиме
- **Файл:** `auth/src/main/scala/com/shevchyk/auth/config/JwtConfig.scala` (строка 26)
- **Проблема:** Fallback secret `"dev-jwt-secret-change-in-production..."` — если забыть задать `JWT_SECRET`, приложение стартует с известным секретом.
- **Исправление:** Убрать fallback. Приложение должно падать при старте без `JWT_SECRET` в любом окружении.

### 2.2 Default DB Credentials
- **Файл:** `core/src/main/scala/com/shevchyk/core/database/DatabaseConfig.scala`
- **Проблема:** Fallback `user=oktopus, password=oktopus`. Аналогично JWT — риск запуска с дефолтными credentials.
- **Исправление:** Убрать fallback для production профиля.

### 2.3 [FIXED] Enum Mismatch: person_role vs users.role
> **Исправлено:** Исправлено при merge persons/users (коммит 76c50a3).

- **Файл:** `V1__Create_schema.sql`
- **Проблема:**
  - `person_role` ENUM: `'driver', 'client', 'secretary', 'dispatcher'` (lowercase, нет admin)
  - `users.role` CHECK: `'CLIENT', 'DRIVER', 'DISPATCHER', 'SECRETARY', 'ADMIN'` (uppercase, есть admin)
- **Исправление:** Привести к единому формату. Добавить `'admin'` в person_role или объединить таблицы (см. 1.3).

### 2.4 Missing FK в ride_pool_members
- **Файл:** `V1__Create_schema.sql` (строки 516-527)
- **Проблема:** `ride_id` и `client_id` не имеют `REFERENCES` — нарушена целостность данных.
- **Исправление:** Добавить миграцию с FK constraints.

### 2.5 [FIXED] Нет expiration в таблице tokens
> **Исправлено:** JWT 24h expiration + absolute 90-day session duration.

- **Файл:** `V1__Create_schema.sql` (строки 106-112)
- **Проблема:** Нет колонки `expires_at`. Токены живут вечно в БД. Нет возможности серверной инвалидации по времени.
- **Исправление:** Добавить `expires_at TIMESTAMP WITH TIME ZONE NOT NULL` и фоновую задачу на очистку.

### 2.6 Cross-Company Data Access
- **Файлы:** Несколько Routes файлов
- **Проблема:** Некоторые endpoints проверяют роль пользователя (DISPATCHER/ADMIN), но не проверяют, что запрашиваемый ресурс принадлежит той же компании. Dispatcher компании A может видеть данные компании B.
- **Исправление:** Аудит всех endpoints — добавить проверку `resource.companyId == user.companyId`.

## 3. MEDIUM — Включить в ближайший спринт

### 3.1 In-Memory Rate Limiter
- **Файл:** `auth/src/main/scala/com/shevchyk/auth/middleware/RateLimiter.scala`
- **Проблема:** Хранит state в `Ref` (в памяти). При перезапуске — сброс. При нескольких инстансах — каждый считает отдельно. Также не чистит старые записи — утечка памяти.
- **Текущее влияние:** Низкое (1 инстанс, небольшая нагрузка). Но нужно исправить до масштабирования.

### 3.2 Static TextEditingController (Flutter)
- **Файл:** `web/lib/auth/login_screen.dart` (строки 16-17)
- **Проблема:** `TextEditingController` объявлен как `static` — не вызывается `dispose()`, утечка памяти, stale данные между переходами.
- **Исправление:** Перенести в State класс, вызывать `dispose()`.

### 3.3 Нет явных транзакций для multi-step операций
- **Проблема:** Создание ride затрагивает несколько таблиц, но нет явных транзакционных границ. Частичный сбой оставит данные в inconsistent состоянии.
- **Исправление:** Обернуть multi-step операции в `transact(xa)` одним блоком.

### 3.4 Множественные экземпляры ApiClient (Flutter)
- **Проблема:** Каждый сервис создаёт свой `ApiClient()` вместо shared instance.
- **Исправление:** Использовать DI / singleton.

### 3.5 Нет HTTPS enforcement в Flutter production
- **Файл:** `web/lib/modules/core/services/api_client.dart`
- **Проблема:** Нет проверки, что base URL использует HTTPS в release builds.
- **Исправление:** Добавить assert/check для HTTPS в non-debug mode.

### 3.6 TIMESTAMP без timezone
- **Проблема:** 10+ таблиц используют `TIMESTAMP` вместо `TIMESTAMP WITH TIME ZONE` (expenses, ride_templates, notifications, company_settings, audit_log, ride_ratings, geofences и др.)
- **Исправление:** Миграция на `TIMESTAMPTZ` для всех временных колонок.

## 4. LOW — Техдолг

### 4.1 Hardcoded test credentials в Flutter
- **Файлы:** `test_credentials_card.dart`, `auth_helper.dart`
- **Статус:** Защищено `kDebugMode` — не попадёт в production build. Но лучше вынести в env.

### 4.2 Inconsistent Error Handling в репозиториях
- Часть репозиториев оборачивают ошибки через `.mapError()`, часть — нет. Нужно унифицировать.

### 4.3 Missing Input Validation
- Нет ограничений на длину строковых полей (name, address)
- Нет валидации координат (-90..90 lat, -180..180 lng)
- Нет валидации формата телефонных номеров на бэкенде

### 4.4 Error Logging
- Flutter: только `debugPrint()` — не работает в production
- Backend: inconsistent логирование ошибок между routes
