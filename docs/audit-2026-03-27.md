## 1. CRITICAL — Исправить до продакшена

### 1.1 Multi-tenant data leak в ride-запросах
- **Файлы:**
  - `ride/src/main/scala/com/shevchyk/ride/repository/PostgresRideRepository.scala:127-133`
  - `ride/src/main/scala/com/shevchyk/ride/application/service/RideService.scala`
- **Проблема:** Следующие методы repository возвращают данные ВСЕХ компаний без фильтра по `company_id`:
  - `findByStatus(status)` — строка 127
  - `findAll()` — строка 135
  - `findByClientId(clientId)` — строка 143
  - `findByDriverId(driverId)` — строка 151
- **Эксплуатация:** `GET /api/rides/pending` (RideRoutes) вызывает `findByStatus(Requested)` — dispatcher компании A видит ВСЕ pending rides всех компаний.
- **Также уязвим:** `GET /api/rides/unpaid` — возвращает unpaid rides всех компаний.
- **Влияние:** Утечка бизнес-данных между компаниями. Блокер для multi-tenant deployment.
- **Исправление:** Добавить `AND company_id = $companyId` во все уязвимые запросы. Изменить сигнатуры методов для принятия `CompanyId`.

### 1.2 Fake pagination — загрузка всех записей в память
- **Файл:** `ride/src/main/scala/com/shevchyk/ride/application/service/RideService.scala:557-566`
- **Проблема:** `getRidesByCompanyPaginated()` и `getDriverRidesPaginated()` загружают ВСЕ записи из БД, сортируют в памяти, затем `.drop(offset).take(limit)`.
- **Влияние:** OOM при росте данных. Для компании с 10k rides каждый paginated запрос грузит все 10k в JVM heap.
- **Исправление:** SQL-уровневые `ORDER BY request_time DESC LIMIT $limit OFFSET $offset` в repository.

### 1.3 Rate limit bypass через X-Forwarded-For (из аудита 26.03, не исправлено)
- **Файл:** `api/src/main/scala/com/shevchyk/app/routes/UserRoutes.scala`
- **Проблема:** Доверяет заголовку X-Forwarded-For для определения IP. AuthRoutes корректно использует `remoteAddress`.
- **Исправление:** Унифицировать — везде `remoteAddress`.

## 2. HIGH — Исправить до релиза

### 2.1 WebSocket: Flutter не использует ticket-based auth
- **Backend:** `WebSocketRoutes.scala` — ticket механизм реализован корректно
- **Flutter:** `web/lib/modules/core/services/websocket_service.dart:27` — JWT передаётся как query parameter
- **Риск:** JWT в логах сервера, прокси, CDN
- **Исправление:** Flutter: POST /api/ws/ticket → получить ticket → подключиться с ticket

### 2.2 Schedule queries без company filter
- **Файл:** `PostgresScheduleDayRepository.scala` — `findByDriverId()` не фильтрует по company_id
- **Влияние:** Потенциальная утечка schedule данных между компаниями
- **Исправление:** Добавить company_id фильтр

### 2.3 In-memory filtering вместо SQL
- **Файл:** RideRoutes — `GET /api/rides/client/{clientId}` грузит ВСЕ rides клиента, фильтрует по company в памяти
- **Исправление:** SQL: `WHERE client_id = ? AND company_id = ?`

### 2.4 Нет CORS middleware
- **Файл:** `api/src/main/scala/com/shevchyk/Application.scala`
- **Проблема:** Нет CORS конфигурации. Блокер для web frontend на другом origin.
- **Исправление:** Добавить ZIO-HTTP CORS middleware

### 2.5 Missing FK в ride_pool_members (из аудита 26.03)
- ride_id и client_id без REFERENCES constraints
- **Исправление:** Миграция V7 с FK constraints

### 2.6 Default JWT secret и DB credentials (из аудита 26.03)
- JwtConfig: fallback "dev-jwt-secret-..."
- DatabaseConfig: fallback user=oktopus, password=oktopus
- **Исправление:** Убрать fallback, приложение должно падать без env vars
